# 正式后台开发版：本机使用

当前入口：`http://127.0.0.1:8782/`。旧模拟面板8781及其数据与本后台分开。本阶段可以初始化管理员、登录、登记订单、查看详情和审核出款申请。正式商品Telegram身份入口已接入，须在本机配置Token并明确启动；真实钱包分配、链监听和签名广播仍待接入。

## 启动与首次设置

1. 双击根目录「启动正式后台.cmd」。脚本编译代码并在后台启动本项目服务，已有同项目服务时复用，不会重复打开数据库。
2. 首次页面显示「初始化管理员」。自己填写3至32位字母/数字/下划线账号和至少12字符密码，再重复输入密码。只在本机填写，勿发到聊天。
3. 创建完成自动登录。已有管理员时只显示登录，不提供第二个公开初始化入口。
4. 右上角可切换中文/English；刷新页面保留语言和有效登录会话。

没有默认管理员密码。测试账号 `qa_owner` 只存在于独立临时验收实例，不能登录你的8782后台。

## 页面

- 概览：正式订单、待审核申请、已审核待签名数量及当前数据库类型。
- 网络配置：登记BNB测试网97或主网56与代币合约，配置并启动/停止正式机器人。测试网要使用实际部署的18位测试代币；网络登记不启用收款或广播。当前需要负责人角色才能修改和启停。
- 正式订单：填写真实双方数字ID及各自EVM钱包地址、金额和约定。商品订单详情在机器人已连接后显示邀请链接，双方通过正式机器人确认；后台不提供冒充双方的确认或假注资接口。USDT买卖正式入口当前只读。
- 订单详情：网络、代币、角色及地址、18位精度金额、费用、约定、双方确认、已分配收款地址和入金记录。没有分配地址时显示「尚未分配，请勿转账」。
- 出款审核：由业务流程生成的申请，查看收款地址、金额、手续费及约定，输入审核理由后选择通过或拒绝，再输入 `APPROVE` 或 `REJECT` 确认。通过只进入待签名状态；拒绝转人工处理，资金保留。
- 操作记录：管理员初始化、登录、创建、入金和审核记录。密码和会话原文不写审计。

当前普通订单尚不能走完整链上流程，因此初始出款列表为空是正常情况；不能用模拟版注资接口给本后台生成测试余额。

连接、邀请及私聊操作详见 [正式商品Telegram入口](production-telegram-guide.md)。

## 数据与停止

未配置 `PRODUCTION_DATABASE_URL` 时，本地开发数据在 `data/production-local`，使用PGlite。配置独立PostgreSQL连接后使用PostgreSQL，不能把旧模拟数据目录当成正式数据库。

正式配置使用独立 `.env.production`；模板为 `.env.production.example`，已有文件不要覆盖。启动脚本默认8782，不读取旧模拟版 `.env`。后台日志在 `data/production-service/output.log` 和 `error.log`，服务锁位于 `data/production-service/data`。

负责人登录后，右上角「停止后台」，输入 `STOP` 确认，正常等待请求及数据库关闭。再双击启动脚本恢复。已运行的后台不会因再次双击脚本自动加载新版服务代码；更新后先正常停止，再启动。静态界面修改刷新页面即可加载。

停止本后台不停止旧模拟机器人。不要删除 `.env`、`.env.production` 或任何数据目录来解决启动问题。

当前服务只监听本机，尚不提供HTTPS公网后台、用户/管理员管理界面、钱包签名、正式备份切换或整套服务器部署功能，不能公开暴露或接收真实资金。
# 测试网钱包功能更新

独立收款地址与入金监听现已接入，先仅支持 BNB 测试网；在“网络配置”中操作。详细步骤见 [测试网收款与监听指南](production-wallet-guide.md)。主网真实收款与签名广播仍未启用，前文钱包待接入的描述为历史阶段记录。


## 订单超时与提醒

“网络配置”页面下方“订单超时与提醒”可设置各阶段时限（5至10080分钟）和到期前提醒（0为不提醒，须小于时限）。仅负责人可修改。

| 阶段 | 默认时限 / 提醒 | 到期处理 |
| --- | --- | --- |
| 待双方确认 | 60 / 15 分钟 | 关闭订单 |
| 待入金 | 60 / 15 分钟 | 关闭订单。已分配地址的订单须入金监听已扫过截止时间后2分钟才关闭；监听未运行时不关闭。关闭后到账的款项记为异常入金并转人工，不会重新激活订单 |
| 已入金待交付、待验收、退款协商 | 1440 / 120 分钟 | 转为“超时暂停”：资金保留，普通交付/验收/退款暂停，交易方仍可发起争议 |

- 每次订单进入新阶段时，按当时的配置保存截止时间（数据库触发器统一处理）。修改配置只影响之后进入的阶段；升级前已有的订单在下一次状态变化后开始计时。关闭自动检查后，新进入的阶段不设截止时间，已有截止时间保留，重新开启后补检。
- 到期前提醒和到期通知发给已私聊过机器人的交易双方；提醒不改变订单版本，旧按钮仍有效。Telegram 订单卡显示本阶段截止时间（UTC）。
- 超时暂停的订单列在同一区域。负责人或审核员点击“恢复普通处理”并输入 RESUME，订单回到原阶段并按当前配置重新计时；不放款、不退款，记录操作人。
- 后台每30秒检查一次，与机器人是否运行无关；电脑睡眠或后台停止期间不检查，启动后补检。

## 加密备份与恢复校验

“网络配置”页面底部“加密备份与恢复校验”（仅负责人可见）。

1. 输入两次12至256字符的备份密码，点击“创建加密备份”。备份包含正式数据库（订单、账本、出款、案件、附件）和 `.env.production`（机器人 Token、RPC 地址），用 AES-256-GCM 与 scrypt 加密，保存在 `data/production-backups/backup-<UUID>.escrowprod`。
2. 创建时先导出快照，再在临时副本中重新打开并计算全部表的逐行摘要和账本平衡，摘要来自快照本身；打不开或账本不平衡的快照不会保存。不需要停止后台。
3. 在列表中点击“校验恢复”并输入该备份密码：在 `data/production-restore-checks/<UUID>` 还原一个新副本，比对摘要与账本，配置恢复为 `.env.production.recovered`。不会替换在线数据库，也不会启动副本。

- **平台钱包私钥不在服务器上，也不在这份备份里。** 必须另外保管签名页面第4部分下载的平台钱包加密备份 JSON 和它的密码；数据库备份记录“哪笔钱属于谁”，钱包备份才能动用这些钱。两者缺一都无法完整恢复。
- 密码遗失无法恢复。请把备份文件复制到另一块硬盘或离线介质，与密码分开保管。本功能没有自动定时备份、云端上传或轮换。
- 恢复副本、`.env.production.recovered` 都包含敏感数据，核对后请妥善保管或删除。
- 仅适用于本地嵌入式数据库（PGlite）。配置了 `PRODUCTION_DATABASE_URL` 使用 PostgreSQL 时，请用 PostgreSQL 自带的备份工具（如 pg_dump）。快照按同项目、同依赖版本恢复验证，跨版本恢复未验证。
