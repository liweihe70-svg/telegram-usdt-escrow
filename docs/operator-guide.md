# 模拟版操作手册

适用版本：2026-10-13。商品/服务担保和 USDT 买卖均使用模拟资金；订单、证据、审计记录和账本保存在本机。操作不需要真实转账。

## 1. 打开面板和机器人

1. 双击项目根目录的「启动控制面板.cmd」。浏览器打开 `http://127.0.0.1:8781/`。
2. 在「机器人配置」检查品牌、费率、管理员数字 ID。已有 Token 不会回显；已有配置正常时不要重新填写。
3. 查看机器人状态。已运行时直接使用；停止时点击启动，等到显示运行中，再私聊自己的测试机器人。
4. `/start` 打开首页；`/id` 查看自己的数字 ID。当前测试机器人为 `@fhsdxzbot`，显示名可能与用户名不同，应核对用户名。

控制面板右上角选择中文或 English，浏览器会记住选择。机器人首页语言按钮或 `/language en`、`/language zh` 设置个人语言，两处独立。交易约定和证据内容保留原文。

机器人与面板共用数据。不要同时运行另一份使用相同 Token 的机器人；不要把独立 `npm run bot` 与面板机器人同时启动。

## 2. 只有一个账号时怎么演练

使用已配置的管理员账号发送 `/demo`，选择交易类型、本人角色、金额、约定。对方由系统模拟，无需填写真实对方 ID。

| 商品/服务担保 | USDT 买卖担保 |
| --- | --- |
| 买卖双方确认条款 | 买卖双方确认条款 |
| 买家注入模拟本金及费用 | 卖家注入模拟本金及费用 |
| 卖家声明交付 | 买家声明法币已支付（仅声明演练） |
| 买家验收并确认放款 | 卖家确认法币已到账并确认放币 |
| 模拟本金给卖家，费用记平台 | 模拟本金给买家，费用记平台 |

本人步骤用普通按钮；对方步骤用「模拟对方」按钮。模拟入金和资金操作按页面要求二次确认。默认100本金、5费用，共105模拟 USDT；新订单按配置固定费率。

机器人运行时后台约每3秒处理模拟结算。刷新订单，核对完成状态、余额、出款记录。卡住时先检查机器人状态和最新订单，不连续点击放款。

普通「创建担保交易」需要真实对方数字 ID，不能用同一个账号充当双方。演练按钮只能作用于管理员自己的演练订单。

## 3. 从面板查看和操作

| 页面 | 常用操作 |
| --- | --- |
| 交易概览 | 查看订单统计、托管余额和最近操作。 |
| 全部订单 | 搜索完整订单编号、筛选状态；打开详情查看确认、入金、交付、退款、证据及计时。 |
| 争议处理 | 阅读约定与证据，输入双方分账和理由，核对总额后执行模拟仲裁。 |
| 出款记录 | 核对收款标识、金额、状态及模拟哈希。 |
| 资金账本 | 核对账户余额和账本平衡；异常入金需单独处理，不能直接视为订单正常资金。 |
| 机器人配置 | 保存本机配置、启动/停止机器人，查看超时设置和待处理订单。 |
| 维护与备份 | 加密备份、独立恢复验证、更新并重启。 |

面板输入的买卖身份是本机模拟操作，不是生产管理员授权系统。只在本机使用。

## 4. 退款和争议

退款：入金后由一方申请，另一方同意或拒绝。同意后模拟结算返还本金及费用给入金方；商品是买家，USDT 买卖是卖家。拒绝返回原阶段。先查订单记录再核对资金，不用重新注资来掩盖异常。

争议：交易方私聊发送以下命令，替换完整订单编号和内容；核对申请后确认。

```text
/dispute 完整订单编号 争议理由
/evidence 完整订单编号 文字说明
/evidences 完整订单编号
```

图片/文件：争议状态下，单独发送 JPG、PNG、PDF 或 UTF-8 TXT，在附件说明中填写 `/file_evidence 完整订单编号 说明`。单份不超过5MB，每方每单最多5份，每单合计20MB，本机全部附件合计50MB。无编号或群附件不接收。证据列表可下载；面板可预览图片。

管理员 `/admin` → 待处理争议，阅读后准备分账：

```text
/arbitrate 完整订单编号 买家金额 卖家金额 裁决理由
```

双方金额之和必须等于可分配资金，例如105分为55和50。方案10分钟有效，确认后执行模拟结算。系统不会自动判断商品是否合格，也不会自动裁决争议。

## 5. 超时待处理

未入金到期自动关闭；已经有入金或异常款的订单保留资金并转人工。超时暂停普通交付、放款和退款操作；仍可发起争议，已有争议仍允许证据和管理员仲裁。

管理员可在面板「机器人配置」待处理列表打开订单，或 Telegram `/admin` → 超时待处理，核对后恢复普通处理。恢复只重新计时，不放款、不退款。恢复使用该阶段保存的原时限；修改全局配置不会改掉旧阶段的截止时间。

服务约每30秒检查超时，即使机器人停止仍会检查。通知需要机器人运行；电脑睡眠、服务停止期间不执行，恢复运行后补检。

## 6. 备份、验证与更新

1. 「维护与备份」输入并重复输入自己保管的恢复密码（12至256字符），创建加密备份。密码只填写在本机面板。
2. 选择新备份，输入同一密码，点击验证恢复，确认显示成功。
3. 加密文件在 `data/backups`。附件和整个 `.env` 包含在加密快照中；自行将备份与密码分别保管。
4. 恢复验证生成独立副本，不替换在线数据，不自动启动机器人。真正切换到副本尚无一键流程，需要单独制定恢复操作。
5. 更新使用「更新并重启.cmd」或面板一键更新重启；正常关闭使用「停止控制面板.cmd」。当前版本优先使用这些入口，不直接结束 Node 进程。

## 7. 常见情况

| 情况 | 处理 |
| --- | --- |
| 网页打不开 | 双击启动脚本，检查本机8781地址；仍失败时查看本项目日志，保留数据。 |
| 机器人无回复 | 看配置页是否运行、是否有错误；检查网络及是否存在同 Token 的第二实例。恢复后重新查询订单。 |
| 控制会话失效 | 刷新面板，重新打开订单核对后操作。 |
| 按钮已过期或状态变化 | 刷新订单，用最新卡片，不能依靠旧消息重复确认。 |
| 放款长时间未完成 | 检查机器人运行状态及出款记录；不要创建第二笔结算、修改数据库或重复注资。 |
| 收到超时提醒 | 查看完整订单编号及截止时间，决定继续等待、恢复普通处理或处理争议。 |
| 备份密码错误 | 在本机重新输入；不要向聊天发送密码。忘记密码无法解密备份。 |
| 切换语言后旧消息仍是原语言 | 旧消息不自动重写，刷新订单或打开首页查看新语言。 |

通知成功与本地回执不是一个事务，异常退出时可能重复消息；不能把消息数量当成资金结算次数。以订单、出款和账本记录核对。
