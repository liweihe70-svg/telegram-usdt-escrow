# 完整模拟版使用说明

仅模拟USDT与法币声明，无需也不应转账。机器人和本地面板共用订单、账本与通知任务。

## 一个账号完成演练

需要英文界面时先发送 `/language en`，或在首页选择 **🌐 中文 / English**。切回中文使用 `/language zh`。设置按用户保存，通知采用收件人自己的语言；约定及证据原文保留。在向导中切换语言后会返回当前填写步骤。

在本地面板保存自己的测试Token与管理员数字ID，启动机器人。使用自己的管理员账号私聊发送 `/demo`。

1. 选择商品担保或USDT买卖，选择自己是买家还是卖家。
2. 输入金额与具体交易约定，核对后创建。对方是系统模拟身份，无需输入ID。
3. 确认自己的条款，点击“模拟对方确认条款”，核对并确认演练步骤。
4. 点击“注入足额模拟入金”，核对并确认。
5. 商品：卖家声明交付，买家验收后放款。USDT买卖：买家声明支付法币，卖家确认收款后放币。自己的步骤按正常按钮操作，模拟对方的步骤按专用演练按钮操作。
6. 放款二次确认后，后台约每3秒处理模拟出款与通知；点击刷新订单核对已完成、余额和记录。

后台停止时不会自动结算，重新启动后恢复待结算订单。通知网络失败会重试；未私聊登记的模拟对方不会收到消息。演练按钮仅限创建者管理员，普通交易中不存在这些替身操作。

## 退款

已入金后申请退款，模拟对方可以同意或拒绝。拒绝恢复原状态，同意需确认并进入模拟结算。退款返还本金及费用给USDT入金方：商品是买家，USDT买卖是卖家。

## 争议与证据

从订单复制完整编号，发送 `/dispute 编号 具体理由`，核对后确认。普通放款与退款暂停。

参与方发送 `/evidence 编号 文字说明` 追加证据。每位参与方每单最多10条、每条1000字，不能代替他人提交。`/evidences 编号` 分页阅读；本地面板也可读取。图片和文件应单独发送，在附件说明中填写 `/file_evidence 完整订单编号 说明`，详见 [附件证据说明](evidence-files-guide.md)。不要提交密码、私钥或无关个人信息。

管理员发送 `/admin`，选择待处理争议，阅读约定、理由与证据。发送 `/arbitrate 编号 买家金额 卖家金额 理由` 准备方案。例如应付105时可以分配55与50。合计必须等于可分配金额，本次仲裁不收费用。方案10分钟内有效，二次确认后执行；取消不改订单资金。

## 两个账号的普通流程

普通创建仍需要真实对方的数字ID。邀请链接只引导到订单，不授权陌生人访问。双方分别确认和操作；管理员只负责模拟入金及争议裁决。不得用演练按钮替真实对方确认。

## 更新与验收

修改后执行 `npm test`。运行中的Node服务需要重启才能加载新代码和数据库表。仅停止再启动面板里的机器人不会重新加载Node模块。

更新后先验证 `/start` 出现管理员演练入口、`/demo` 不要求对方ID，再分别验证商品/P2P完成、退款、争议仲裁和模拟余额归零。保留已有 `.env` 和 `data/local-demo`，不要清空数据。

本阶段验收完成的条件是本地自动测试通过且上述新入口在实际Telegram工作。测试代码通过不能代替实际消息收发验收。
