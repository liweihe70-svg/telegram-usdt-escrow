## 资产标识与节点要求

第一期主网仅允许合约 `0x55d398326f99059fF775485246999027B3197955`，按18位精度处理。该资产在生态列表/浏览器中可能显示为 Binance-Peg USDT 或 Binance-Peg BSC-USD，必须以链ID与完整合约识别，不能仅凭“USDT”名字入账。测试网需单独配置18位测试代币，不能把主网合约地址直接当作测试网代币。

节点必须支持 `eth_getLogs` 与 finalized 区块读取。BNB官方说明部分公开主网端点关闭日志接口，不能直接选这些端点做入金监听。启动时仍需在实际节点核验合约代码和 decimals，不以文档替代链上检查。

参考：[BNB节点与链ID](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/json-rpc-endpoint/)、[BNB最终确认接口](https://docs.bnbchain.org/bnb-smart-chain/developers/json_rpc/bsc-api-list/)、[PancakeSwap资产列表](https://github.com/pancakeswap/token-list/blob/main/src/tokens/pancakeswap-extended.json)、[ethers读取接口](https://docs.ethers.org/v6/api/providers/)、[node-postgres事务](https://node-postgres.com/features/transactions)。

## 下一批实现顺序

1. 正式数据库迁移、管理员初始化和登录面板；模拟与正式配置/数据/端口隔离。
2. 真实参与方及收款地址登记，正式订单创建、邀请、双方确认与状态机；没有模拟对方和注资按钮。
3. 每单专属平台收款地址，链扫描进度与最终确认事件持久化；重复、少付、多付、迟到入金分别记账和对账。
4. 双方完成验收/退款或管理员裁决后生成待审核出款；审核通过才进入签名队列，审批绑定收款地址、金额和订单版本。
5. 独立签名服务核对审批、限额、链和代币；持久化nonce与签名交易身份，广播重试不生成第二笔付款。主服务不保存钱包私钥。
6. 链上最终回执核对与余额对账、BNB手续费供应、异常任务处理、通知、争议附件和备份。
7. 本地可操作后台与Telegram联调，输出部署包、初始化步骤、密钥配置及恢复说明。

账户地址与HD路径分配需使用数据库唯一约束；只使用公共派生信息的主服务不能执行硬化派生。每单EOA地址要考虑BNB gas，不能假设“钱包有USDT就能转出”。正常放款、退款和仲裁均经过审核；管理员审核不能绕过双方条款或订单余额。
