# 本地维护与备份

本阶段交付仍为模拟资金版本。加密备份和恢复验证在本机进行。

## 一键维护

- `启动控制面板.cmd`：编译并启动；新版已经运行时直接打开页面。
- `更新并重启.cmd` 或面板「维护与备份 → 一键更新并重启」：先编译，成功后通过受保护的本机接口正常停止机器人与数据库，等服务锁释放后启动。原本运行中的机器人会尝试恢复连接；连接失败会显示失败状态，需要检查本机网络。
- `停止控制面板.cmd`：正常停止当前项目的服务。

管理器验证 application、workspaceId、instanceId，拒绝停止其他项目、变化的实例或未支持该接口的旧服务，不使用操作系统强制结束进程。编译失败时保留原服务。后台日志在 `data/maintenance-output.log`、`data/panel-output.log`，任务状态在 `data/maintenance-status.json`。

从旧服务迁移需要手动重启一次：在面板停止机器人，再结束监听 8781 的旧 Node 进程，双击启动脚本。以后使用上述正常停止接口。不可同时运行独立 `npm run bot` 和控制面板中的机器人。

## 加密备份

在「维护与备份」输入 12 至 256 字符的恢复密码并再次确认。密码仅用于当次本机请求，不写入配置、数据库或日志。使用 AES-256-GCM 和 scrypt 加密 PGlite 快照及整个 `.env`。公开清单只包含日期、文件名、大小和记录统计。

创建时暂停 HTTP 写入、停止并等待机器人处理和结算任务结束，生成快照，结束后恢复原本运行中的机器人。正在进行的 Telegram 更新会按正常停止流程处理。备份文件在 `data/backups/backup-<UUID>.escrowbak`；相邻 JSON 是展示元数据，不应单独当作可信恢复证据。

密码遗失无法恢复。请自行把加密文件与密码分别保管。本功能没有云端上传、定时备份或备份轮换。

## 验证恢复

选中备份并输入原密码，生成新目录 `data/restore-checks/<UUID>`，不覆盖在线数据库。恢复后对全部 public 表逐行内容计算摘要，比较备份时的摘要，并检查全局及每批账目守恒。配置恢复到 `.env.recovered`，该文件含敏感配置，需私下保管。副本不会自动启动机器人，也不会自动替换在线数据。

快照基于 PGlite 的物理数据目录接口，当前验证的是同项目、同依赖版本恢复；跨版本迁移未验证。恢复副本、备份和日志均位于忽略的 data 目录，不应公开分享。验证失败可能留下未完成副本，需核对后人工清理。
