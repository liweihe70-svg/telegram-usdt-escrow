# 担保群与订单绑定

本功能使用模拟资金，已完成离线逻辑测试；实际双账号、Telegram 群权限及通知送达验证按用户要求留到最后。

## 使用流程

1. 在私聊创建普通订单，买卖双方数字 ID 固定。双方最好都先私聊机器人发送 `/start`，以便接收私人通知。
2. 手动创建 Telegram 群，邀请交易双方，添加机器人并设为群管理员。只邀请可信成员：所有群成员都可以看见被展示的交易信息。
3. 订单仍处于待双方确认时，由交易方兼群管理员发送 `/bind 完整订单编号`。私聊订单卡也有「添加到担保群并申请绑定」入口。
4. 另一位交易方在30分钟内点击「同意在本群展示订单」。未同意之前只展示绑定提示，不展示交易约定。
5. 群绑定同意与交易条款确认是两步。绑定完成后，双方分别用标有买家或卖家的按钮确认交易条款。
6. 模拟入金仍由本机面板或私聊的测试管理员完成。商品由卖家声明交付、买家确认放款；P2P由买家声明法币付款、卖家确认放币。普通退款需要另一方同意，放款、同意退款及关闭订单保留二次确认。
7. 争议理由、文字证据和管理员仲裁继续在私聊处理。群订单卡提供私聊入口；结算状态会通知群。

本阶段要求机器人为群管理员，以可靠核验发送者成员身份和管理员身份。Telegram官方说明，对其他用户调用 getChatMember 的有效性仅在机器人为群管理员时得到保证：[getChatMember](https://core.telegram.org/bots/api#getchatmember)。不需要自动提升交易双方的群权限，也不会代替用户建群或修改权限。

## 群命令

| 命令 | 用途 |
|---|---|
| `/group` | 显示本群订单；未绑定时给出说明 |
| `/bind 完整订单编号` | 交易方兼群管理员申请绑定 |
| `/group_language en` 或 `zh` | 交易方兼群管理员设置共享群语言，不改变私人语言 |
| `/unbind` | 交易方确认撤销群绑定；订单仍保留，私聊仍可继续 |
| `/group_resume` | 交易方兼群管理员恢复因通知失败而暂停的绑定 |

每个群同时只绑定一笔订单，订单不能覆盖或转移到另一个群。解绑后若需再次建立绑定，使用新订单。系统模拟对方（单账号 `/demo`）不能替代第二方同意公开群信息，因此不能绑定群。

群内普通聊天、发给其他机器人的命令和匿名管理员发言不会当作订单操作。群按钮包含角色及订单信息，始终重新校验真实点击者、聊天范围和当前绑定；复制旧按钮不能跨群操作。群不会覆盖私聊联系人或创建向导。

## 通知和运行

群通知有独立持久记录。私聊发送成功后，群发送失败不会阻塞私聊重试。群失败每30秒重试，某条通知连续5次失败会暂停绑定；权限和网络恢复后可 `/group_resume`。机器人退出或失去管理员身份的更新会暂停活跃绑定，恢复管理员身份后恢复。一般群升级为超级群时迁移绑定及发送记录，旧群按钮失效。

消息发送与发送记录之间如发生进程崩溃，状态消息可能重复；业务状态及出款仍按事务和幂等校验处理。本功能不承诺 Telegram 通知严格只发送一次。

控制面板订单详情可查看群 ID、绑定状态及群语言。绑定表、双方同意及通知记录均进入既有加密数据库快照。话题隔离、自动置顶、管理员权限自动配置尚未实现。图片和文件证据已支持私聊提交，群内附件不接收，见 [附件证据说明](evidence-files-guide.md)。

## 测试与预览

新增8项测试覆盖双方同意与待确认信息保护、管理员与角色权限、跨群旧按钮、唯一绑定及到期、商品及P2P全流程、退款、撤销、共享语言、群迁移与通知记录、重复update，以及发送失败暂停恢复。

全部59项自动测试通过；补充迁移发送记录处理后，8项群测试再次通过。离线模拟不能替代最终真实双账号验收。

`npm run build` 后可运行 `node scripts/preview-groups.mjs` 创建独立控制面板预览，包含活跃及待确认的合成绑定。预览使用系统分配端口，没有真实 Token、群或资金，不修改既有8781订单。
