# 正式商品担保：Telegram身份入口

正式商品订单已接入私聊身份、邀请、双方确认、交付声明、验收申请管理员审核以及状态通知。测试网独立地址分配与入金监听现已接入，须另外配置公开收款分支和RPC并明确启动。主网收款与放款广播仍未启用，USDT买卖订单暂时只读。见 [测试网钱包与监听](production-wallet-guide.md)。

## 连接机器人

1. 登录8782正式后台，进入「网络配置」，下方「正式 Telegram 机器人」。
2. 只在本机 Token 输入框填写自己的测试机器人 Token，点击保存。凭据写入独立 `.env.production`，不会在页面回显，也不会写入订单审计或聊天。
3. 如使用旧模拟版的同一机器人，先停止旧模拟机器人。不能同时用相同Token启动两份长轮询；新版会检查可访问的8781模拟服务，发现同一机器人活跃时拒绝启动，其他外部实例仍需自行核对。
4. 点击「启动正式机器人」，阅读切换说明，输入 `START` 确认。等待显示运行中与实际用户名；连接失败时检查本机网络和Token，不要把凭据发到聊天。
5. 本人私聊发送 `/start`、`/id`，可 `/language en` 或 `zh` 切换。菜单提供「我的订单」。

当前正式机器人不会自动启动；保存Token不建立轮询。停止或重启后台后，需要再次明确点击启动。Token与旧模拟版 `.env` 分离，不读取旧Token，也不修改旧模拟订单。

## 创建与邀请

1. 买卖双方都先私聊机器人 `/start`、`/id`，将自己的数字ID和准备使用的钱包地址交给登记订单的负责人。
2. 在正式后台登记商品订单，明确交付约定，核对双方数字ID、各自地址、金额和费用。
3. 机器人已成功连接后，商品订单详情显示「邀请交易方」链接。把该链接给订单指定双方；邀请本身不授予他人权限。
4. 交易方打开邀请，看到自己的订单约定、角色、金额、链和钱包地址，点击「确认条款和本人钱包地址」。任一方未确认时仍等待双方确认。
5. 同一Token下，旧模拟订单不会出现在新入口；不是指定买卖方不能查看订单。正式版没有模拟对方确认或假注资按钮。

没有第二账号时，可以先验证本人ID、语言、订单查看及本人的条款确认；不能用假对方ID完成另一方确认。钱包地址若填错，应在未确认/未入金时先停止推进并处理订单，当前版本不提供地址修改界面。

## 后续交易操作

双方确认后进入待入金。如果测试网收款分支和监听已配置且处于运行中，监听器为此商品订单分配独立地址；买家在机器人中刷新订单查看地址，只能转入该订单指定的测试代币及完整应入金额。没有地址、监听停止或只有一方确认时不要转账。页面的测试钱包第一个子地址预览不等于已分配订单地址。

内部流程在隔离测试中已验证：已核验入金 → 卖家声明交付 → 买家验收并申请审核 → 二次确认金额及收款地址 → 生成后台待审核出款。管理员通过审核后仍等待独立签名服务，不直接转账。旧版本按钮、错误角色、重复更新不能绕过当前状态和身份。

双方的操作会写入不可变交易方记录，后台「操作记录」可查看。交易状态事件与通知在同一业务事务内保存；仅向私聊登记过的双方发送，按各自语言生成，失败从30秒开始延迟重试、最多延迟1小时。旧订单版本通知会跳过。

发送成功与收据落库不是同一事务，异常退出仍可能重复一条提示；不能用消息数量判断资金变化。重复Telegram更新已领取但处理状态不明时，系统要求从「我的订单」刷新核对，不盲目再执行。

## 当前限制

仅私聊商品主流程。群绑定、用户自助创建向导、正式退款/争议/附件/超时、管理员通知入口尚未移植；旧模拟版存在这些功能，不等于已经接入正式流程。只有该订单分配了平台测试地址且监听运行，机器人订单页才展示测试网收款提示；旧消息不能反映当前状态，应刷新订单核对。

钱包分配与测试网入金监听已实现，下一阶段接独立签名和出款对账。后台只存公开xpub，不持有钱包私钥。两账号真实确认和链上完整订单联调仍需最终验收，不能用后台代确认或合成测试冒充真实联调。

## 争议附件（图片与文件）

订单进入争议后，买家或卖家在与机器人的私聊中直接发送图片或文件，并在附件说明（caption）中填写：

```
/file_evidence 完整订单编号 证据说明
```

- 支持 JPG、PNG、PDF、UTF-8 TXT，按扩展名和文件内容校验（不是病毒扫描）。单份最多5MB；每方每单最多5份，每单合计20MB，后台合计100MB。Telegram 会把直接发送的照片转成 JPEG。
- 只有争议处理中的订单双方可以提交；身份、订单状态和说明格式核对通过后才下载文件，保存前会在锁内再次确认订单仍在争议中。同一个 Telegram 文件重复发送或更新重放不会重复保存。
- 每次保存会在案件记录中写入一条 PARTY_FILE（文件名、大小、SHA-256、说明），并通知双方。附件和记录都不能修改或删除。
- 争议订单卡新增“争议附件”按钮，或发送 `/evidences 完整订单编号`，列出全部附件；点击下载按钮由机器人把文件发回。只有订单双方能列出和下载。
- 管理员在后台“退款与争议”打开案件，可预览图片、下载全部附件并核对 SHA-256。下载需要已登录的后台会话；文件总是以附件或受沙箱限制的图片返回，不会作为网页打开。

## 担保群（只展示，不在群里动资金）

群只用来向双方和群成员展示订单与状态通知。**确认条款、声明交付、验收放款、退款、争议、附件都仍在私聊完成**；群订单卡只有“刷新”和“去私聊处理订单”跳转链接，没有任何能改变订单或资金的按钮。这样群里的代点、旧按钮跨群、冒充角色等问题都不会影响资金。

### 使用流程

1. 在私聊/后台创建订单，买卖双方数字 ID 固定。双方最好先私聊机器人 `/start`。
2. 手动建群，只邀请交易双方和可信成员，添加机器人并**设为群管理员**（机器人需要管理员身份才能可靠核验成员和管理员）。所有群成员都能看到展示的订单信息。
3. 订单仍为“待双方确认”时，**交易方兼群管理员**发送 `/bind 完整订单编号`。此时群里只显示“绑定待确认”，不显示约定内容。
4. 另一位交易方（须是群成员）30分钟内点击“同意在本群展示订单”。双方同意后才展示订单：状态、金额、条款确认情况、收款地址、截止时间和交易约定。群绑定同意不等于确认交易条款。
5. 之后该订单的状态通知除私聊外也会发到群里；只推送绑定生效后产生的事件。

### 群命令

| 命令 | 谁可以用 | 作用 |
| --- | --- | --- |
| `/group` | 群成员 | 显示本群订单；未绑定时显示说明 |
| `/bind 完整订单编号` | 交易方兼群管理员 | 申请绑定 |
| `/group_language en` 或 `zh` | 交易方兼群管理员 | 群共享语言，不改个人语言 |
| `/unbind` | 交易方（群成员） | 二次确认后撤销绑定；订单继续在私聊进行 |
| `/group_resume` | 交易方兼群管理员 | 恢复暂停的绑定（机器人须仍为管理员） |

- 一个订单一生只能绑定一个群；一个群同时只绑定一单。撤销后不能把同一订单再绑到别的群，需用新订单。
- 普通聊天、发给其他机器人的命令、匿名管理员和频道身份发言一律忽略。按钮都核对点击者身份和当前绑定订单，撤销后旧按钮失效。
- 群通知与私聊通知分开记录：群发送失败不影响私聊，30秒后重试；同一条连续失败5次，或机器人被移出/取消管理员，绑定转为“暂停”，恢复权限后用 `/group_resume`。普通群升级为超级群时绑定随新群 ID 迁移。
- 后台订单详情显示绑定的群 ID、状态、暂停原因和群语言。

### 双账号验收清单（待有第二个账号后执行）

- [ ] 机器人为群管理员；A（群管理员、买家）`/bind`，群里只显示待确认，不显示约定。
- [ ] 非交易方群成员点击“同意”被拒绝；B（卖家）点击后显示订单详情，双方私聊收到绑定通知。
- [ ] 群订单卡只有刷新和私聊跳转；在私聊确认条款后，群收到状态更新。
- [ ] `/group_language en` 后群卡片变英文，A、B 个人语言不变。
- [ ] 取消机器人管理员 → 绑定暂停；恢复后 `/group_resume` → 补发未送达的群通知。
- [ ] `/unbind` 二次确认后旧群按钮失效，私聊订单不受影响。
