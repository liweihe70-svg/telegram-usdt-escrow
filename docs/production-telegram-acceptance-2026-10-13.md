# 正式Telegram入口开发验收

2026-10-13：源码编译与前端JavaScript语法检查通过。生产模块测试从17项增加到24项，全部通过。

| 新增测试 | 结果 |
| --- | --- |
| 指定交易方邀请 | 非参与方拒绝；ID与私聊chat ID一致；条款及钱包确认正确，语言与确认记录重建控制器后保留。 |
| 交付与验收审核 | 卖家交付、买家二次确认申请审核；错误角色和旧按钮拒绝；只有一个待审核申请，托管余额仍保留。 |
| 重复更新 | 相同update不重复操作，缓存响应不能交给另一身份；处理中断的已领取更新要求刷新核对。 |
| 通知 | 旧版本通知跳过；收件人语言正确，失败延迟重试，只补发尚无成功收据者。 |
| 实际SDK处理路径 | 使用Telegraf合成update和受控IO；身份取自from.id，群消息忽略，伪造回调身份不能代替交易方。 |
| Token保存和并发 | 合成配置保留其他字段，替换重复Token字段；非法输入不写入；保存时禁止并发启动，状态不回传Token。 |
| 受保护HTTP | Token配置须OWNER和CSRF，保存后仍停止；不会自动接收消息。 |

测试使用隔离PGlite、合成双方身份和回执，未连接真实Telegram、BNB RPC或签名服务。本轮不把SDK合成update测试表述成真实消息收发或双账号验收。

用户正常停止8782后，已启动新服务并核对管理员初始化状态保留。实际收款与广播仍关闭，未登录机器人状态接口返回401。浏览器自动化连接中断，新增Token配置/启停/邀请界面未进行浏览器实测；界面语法及对应HTTP接口测试通过。

旧模拟数据与 `.env` 不受新正式接口影响。新机器人Token只通过用户本机配置或独立 `.env.production` 提供，没有默认Token，也没有从旧模拟版自动导入。
